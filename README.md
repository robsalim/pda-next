# PDA Next (Rust)

Приложение для сбора, регистрации и визуализации данных с промышленных контроллеров (Siemens S7, Modbus TCP). Ведёт собственную историю сигналов (Historian), отображает живые графики и временные диаграммы, а также транслирует их через встроенный веб-вьювер.

Самостоятельное приложение: один self-contained exe, без интерпретаторов и внешних зависимостей. Стартовая страница открывается мгновенно, опрос драйверов и запись в БД работают в асинхронном рантайме tokio.

## ⚡ Возможности

### Промышленные драйверы

- Siemens S7-300 / S7-400 / S7-1200 / S7-1500 — **собственный транспорт S7 (`s7_proto`)**, библиотека `snap7.dll` больше не нужна.
- Siemens S7-200 SMART (прямая адресация V-памяти: VW100, VD20, V100.3).
- Siemens LOGO! 8 (0BA8/0BA2) — через тот же драйвер `snap7 (S7-200 SMART)` с Connection type = 3 (Basic): все ресурсы контроллера (I, Q, M, AM, аналоговые каналы AI/AQ) лежат в одной фиксированной карте VM, видимой как DB1 (`VW1032` = `DB1.DBW1032` — аналоговый вход AI1). Аналоговые каналы — **WORD по 2 байта** со значением `0..1000` (1000 = 10 В), тип в программе `INT16`, а не FLOAT: AI1=VW1032, AI2=VW1034, AQ1=VW1072, AM1=VW1118; канал = начало области + (номер−1)×2. Физический масштаб задаётся в диалоге переменной (`Scale = 0.01`). Полная карта памяти и настройка TSAP — во вкладке Help, п. 4.
- Modbus TCP-клиент (Master) на `tokio-modbus`.
- Встроенный Modbus TCP-сервер (Slave/Bridge), порт по умолчанию 502.

### Вкладка I/O Configuration

- Иерархическое дерево модулей и групп сигналов.
- Таблица тегов со значениями в реальном времени (WebSocket-подписка `/api/live/ws`).
- Импорт/экспорт конфигурации в форматы CSV и JSON.
- CSV-колонка `LogIntervalMs` — период записи в архив (мс); у новых переменных по умолчанию 0 (запись только по изменению, COV).
- Массовое копирование переменных со сдвигом адресации.
- Валидация адресов и автоподсказки формата прямо в диалоге тега.
- В статусе модуля — сводка опроса: `9.8 мс/цикл · 102 Гц · N сигн./M запр.`, с флагом ПЕРЕГРУЗ если чтение дольше заданного периода (S7 и Modbus-клиент).

### Вкладка Charts (Тренды)

- Живые и архивные графики на движке uPlot с поддержкой Drag & Drop из дерева сигналов.
- Сигналы BOOL рисуются цифровыми дорожками внизу окна (как временные диаграммы): импульс 0→1 занимает 4% высоты, дорожки идут стопкой без наложений в порядке легенды (первый BOOL — верхняя полоса), уровень 1 залит сплошь цветом сигнала; автомасштаб Y считается только по аналоговым.
- Измерительные курсоры X1/X2 с расчётом разницы во времени (ΔT) и точных значений по оси Y в легенде.
- Мультиоконный режим графиков на одной рабочей панели.
- Мини-обзор текущего архивного окна в режиме Archive (границы оси всегда совпадают с «Начало»/«Длительность» панели): интервалы без данных подсвечены красным (REST `/api/gaps`), двойной клик по красной полосе выделяет пропуск, кнопка **⤓ Выбранное** грузит выделенное окно на основной график.
- Навигация по времени как в pyqtgraph: колесо мыши — мгновенный зум, перетаскивание за нижнюю ось — сдвиг окна (на оси — зелёный курсор-«рука»). При выходе за загруженный интервал данные подгружаются **сразу на первом шаге зума** (не по окончании вращения) и с запасом в один экран по обе стороны, поэтому края графика не пустуют. **При приближении (зум in) окно перезапрашивается с более мелким шагом**: короткая вспышка сигнала, неразличимая на общей сетке, появляется после приближения — а не остаётся размазанной. Прореживание сервера отдаёт до 5000 точек на серию, а интервалы без реальных записей (хвост «в будущее» после последней точки, простой оборудования) приходят как `null` — uPlot обрывает линию, а не дорисовывает её горизонтально. Кнопки в шапке: **🔍 100%** — полный диапазон с перезапросом с сервера, **x→ 100%** — автомасштаб по времени без пересоздания графика, **↑y 100%** — вписать кривые в текущее окно по времени.

### Вкладка Bits (Дискретный анализ)

- Автоматическая распаковка байтовых и целочисленных регистров (BYTE, INT16, UINT16) в битовую маску с построением временных диаграмм.
- Bit 0 — верхняя дорожка, цвета кривых закреплены за номером бита.
- Переключатель порядка байт `Hi-Lo / Lo-Hi` для 16-битных слов (Siemens отдаёт старший байт первым).
- Зум колесом, пан за нижнюю ось и автомасштаб по времени **x→ 100%** работают так же, как на Charts; при зуме out края графика догружаются с сервера автоматически, при зуме in окно перезапрашивается с более мелким шагом (короткие битовые всплески становятся различимы). Фоновое обновление Live не сбрасывает пользовательский зум.

### Встроенный Modbus TCP-сервер (Slave/Bridge)

- Принятая от Master'а посылка уходит в БД **сразу**, не дожидаясь общего цикла журнала: после записи (FC 5/6/15/16) точки этих тегов забираются из реестра и флашатся в историю с меткой времени приёма. Общий скан журнала не создаёт дублей — забранные переходы помечаются зарегистрированными.

### Архиватор (Historian)

- Буферизованная асинхронная запись в БД пачками (Batch-режим).
- Фильтрация по изменению (Change of Value / COV), интервалу и зоне нечувствительности (deadband).
- Двойные переходы между сканами (100→101→100) не теряются: накапливаются до 8 незаписанных значений на тег.
- Автоматическая очистка старых данных по сроку хранения (Retention Policy).

### Встроенный веб-сервер

- Тот же интерфейс в любом браузере (<http://localhost:8082>): REST + WebSocket поверх axum, статика из `web/`.
- Desktop-оболочка и браузер используют один и тот же фронтенд и один и тот же серверный код.
- Мобильная мини-версия `m.html` — для телефонов и планшетов (по IP машины в локальной сети); десктопный `index.html` перенаправляет на неё тач-устройства автоматически, ручной выбор — `?desktop=1` / `?mobile=1`.

### Темы оформления

- Тёмная и светлая тема интерфейса с сохранением состояния в localStorage.

### Вкладка Help

- Справочное руководство прямо в приложении: первый запуск, диагностика статуса, настройка I/O, форматы адресов, расчёт минимального времени опроса, работа с Charts/Bits и веб-клиентом.
- Справочник адресов генерируется автоматически из драйверов — не устаревает при добавлении новых протоколов.

## 💾 Выбор и сравнение баз данных

| СУБД | Преимущества | Недостатки | Рекомендуемый сценарий |
|---|---|---|---|
| **SQLite** (по умолчанию) | • Работает «из коробки», не требует установки стороннего ПО.<br>• Вся база хранится в одном локальном файле (data/pda_local.db).<br>• Нулевые затраты на администрирование.<br>• Минимальное потребление ОЗУ. | • Блокировка на уровне файла при записи (не рассчитана на сотни параллельных клиентов).<br>• Падение производительности при архивах > 15–20 ГБ.<br>• Ограниченные возможности удалённого подключения к файлу базы. | Локальные стенды, переносные ноутбуки наладчиков, небольшие машины (< 200–300 тегов с записью 1 раз в секунду). |
| **PostgreSQL** | • Высокая надёжность транзакций (ACID) и стабильность.<br>• Отличная масштабируемость при сотнях параллельных запросов.<br>• Полноценный сетевой доступ (к одной БД могут обращаться несколько операторов/инженеров).<br>• Развитые инструменты резервного копирования и репликации. | • Требует установки и первоначального администрирования сервера PostgreSQL.<br>• Требует больше ресурсов системы (ОЗУ, CPU) по сравнению с SQLite. | Постоянно работающие цеховые SCADA-станции, диспетчерские посты, средние и крупные проекты (> 500 тегов). |
| **PostgreSQL + TimescaleDB** | • Специализированная оптимизация под временные ряды (Time-Series Data).<br>• Автоматическое секционирование (чанкирование) по времени.<br>• Аппаратное сжатие данных (экономия до 70–90% дискового пространства).<br>• Молниеносная выборка исторических трендов за большие периоды. | • Необходима установка расширения TimescaleDB поверх PostgreSQL.<br>• Чуть более сложная процедура настройки политик сжатия и ротации. | Крупные архивы, высокая частота опроса (10–100 мс), сотни и тысячи аналоговых тегов с хранением истории за месяцы и годы. |
| **MySQL / MariaDB** | • Широкая распространённость и простота интеграции с веб-инфраструктурой предприятия.<br>• Быстрая обработка простых операций вставки/чтения.<br>• Наличие удобных графических инструментов (DBeaver, phpMyAdmin, MySQL Workbench). | • Менее эффективна для аналитических запросов по скользящим окнам времени, чем TimescaleDB.<br>• Менее гибкая система расширений под временные ряды. | Предприятия, где сервер MySQL/MariaDB уже развернут и поддерживается штатными администраторами. |

**Настройка СУБД в программе:** переключение типа базы и ввод параметров подключения (хост, порт, логин, пароль, имя базы) осуществляются во вкладке **Database** — настройки сохраняются в `db_config.json` (файл защищён от попадания в git-репозиторий). Сервер ищет этот файл рядом с exe, в текущей папке и в `rust_pda/`.

## 💻 Системные требования

- **ОС**: Windows 10/11 (или Windows Server 2016+)
- **Никаких рантаймов и зависимостей** — в собранном виде это самостоятельные exe-файлы.
- **WebView2**: требуется для desktop-оболочки (`pda-desktop.exe`); в Windows 10/11 обычно уже установлен. `WebView2Loader.dll` кладётся рядом с exe.
- **snap7.dll не нужен**: протокол S7 реализован нативно в `pda-core`.

## 📥 Способы установки

### Вариант 1. Готовая сборка из Releases (рекомендуется)

1. Откройте страницу [Releases](https://github.com/robsalim/pda-next/releases) и скачайте архив `PDA-Next-v<версия>-windows-x64.zip`.
2. Распакуйте в любую папку (например, `C:\SCADA\pda-next`).
3. Запустите `pda-desktop.exe` — приложение откроется в нативном окне.
   Для работы только через браузер запустите `pda-server.exe` и откройте <http://localhost:8082>.

### Вариант 2. Сборка из исходников

```bat
git clone https://github.com/robsalim/pda-next.git
cd pda-next
cargo build --release
```

Бинарники появятся в `target\release\`: `pda-server.exe`, `pda-desktop.exe`. На тулчейне `windows-gnu` build.rs автоматически кладёт `WebView2Loader.dll` рядом с exe; статика `web/` берётся из корня проекта (рядом с `Cargo.toml`) или из папки `web` рядом с exe.

## 🚀 Запуск программы

### Desktop (нативное окно)

```bat
pda-desktop.exe
```

Окно WebView2 с тем же интерфейсом; сервер стартует внутри на `127.0.0.1` с эфемерным портом, поэтому не конфликтует с автономно запущенным `pda-server` (8082).

### Режим «только просмотр» (вторая копия рядом с рабочей)

```bat
pda-desktop.exe --view-only
:: или: set PDA_VIEW_ONLY=1
```

Опрос модулей не запускается вообще: порты (в том числе Modbus 502) свободны, работают история, графики и архив. Заголовок окна — «PDA Next — только просмотр». Тот же ключ понимает и `pda-server.exe` (`pda-server.exe --port 9000 --view-only`).

Уже запущенное приложение можно перевести в этот режим без перезапуска — кнопкой **⏸ Опрос** в шапке (освобождает порты, история остаётся доступной).

Ярлыки для запуска создаёт скрипт:

```bat
powershell -ExecutionPolicy Bypass -File .\make_shortcut.ps1
```

Рядом с `pda-desktop.exe` появятся «PDA Next» и «PDA Next — просмотр» (с `--view-only`). Ключ `-Desktop` дополнительно кладёт ярлык просмотра на рабочий стол, `-Exe`/`-Dest` задают путь к exe и папку для ярлыков.

### Сервер (через браузер)

```bat
pda-server.exe
```

Веб-интерфейс доступен по адресу <http://localhost:8082>. Параметры можно переопределить без пересборки:

```bat
pda-server.exe --host 0.0.0.0 --port 9000
:: или через окружение: PDA_HOST / PDA_PORT
```

## ⚙️ Конфигурация (crates/pda-core/src/config.rs)

| Параметр | Описание |
|---|---|
| `DB_CONFIG` (db_config.json) | Базовые параметры подключения к СУБД по умолчанию. |
| `WEB_HOST`, `WEB_PORT` | Сетевой интерфейс и TCP-порт встроенного веб-сервера (по умолчанию 0.0.0.0:8082 — доступен и по `127.0.0.1`/`localhost`, и по адресу машины в сети, т.е. с телефона открывается `http://<ip>:8082/m.html`; оставить только loopback — `--host 127.0.0.1`). |
| `DEFAULT_MODBUS_SERVER_PORT` | Порт встроенного Modbus TCP-сервера (по умолчанию 502; для порта 502 могут потребоваться права администратора). |
| `JournalConfig` | Настройки историка: период сканирования и флеша, размер пачки INSERT, глубина буфера, retention_days. |

## 📁 Структура проекта

```
rust_pda/
├── Cargo.toml              # Workspace: pda-core + pda-server + pda-desktop
├── crates/
│   ├── pda-core/           # Ядро системы (без HTTP и UI):
│   │   ├── config.rs       #   Константы и JournalConfig
│   │   ├── models/         #   Теги, соединения, точки данных
│   │   ├── core/           #   TagRegistry, TagPoint, Historian
│   │   ├── database/       #   DbService (SQLite/PostgreSQL/MySQL), Collector
│   │   └── drivers/        #   snap7 (собственный s7_proto), S7-200 SMART,
│   │                       #   modbus_client (tokio-modbus), modbus_server
│   ├── pda-server/         # HTTP+WebSocket сервер (axum) и библиотека AppCore:
│   │   ├── src/main.rs     #   автономный запуск сервера
│   │   ├── src/api.rs      #   REST-эндпоинты
│   │   ├── src/ws.rs       #   live-рассылка значений по WebSocket
│   │   └── tests/smoke.rs  #   смоук-тест REST+WS+Modbus в процессе
│   └── pda-desktop/        # Нативная оболочка: окно tao + WebView2 (wry),
│                           # внутри — тот же pda-server и тот же фронтенд
└── web/                    # Unified-фронтенд (HTML/JS, uPlot): вкладки
                            # Charts, Bits, I/O, Database, Help
                            # (index.html — десктоп, m.html — мобильная версия)
```
